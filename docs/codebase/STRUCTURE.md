# Codebase Structure

## 1) Top-Level Map
frontend/: sole React app. backend/src/docintel/: sole API/domain/services/repository/storage. pipeline/src/document_pipeline/: OCR/extraction implementation. contracts/: generated public schemas/OpenAPI/examples. data/: fixtures + 150 synthetic product parents. evaluation/: evaluator evidence, not inference input. scripts/: dev/generators/verification/backup. runtime/: ignored data/models/reports. homework/: index to historical submission refs.

## 2) Entry Points
docintel.api.app:create_app/app; LocalInferenceWorker composed at lifespan for tesseract only. document-infer CLI in pipeline. scripts/dev.py selects root-relative commands. Vite frontend/src/main.tsx mounts app. API types generated by frontend/scripts/contracts.mjs from contracts/generated/openapi.json.

## 3) Module Boundaries
API owns HTTP/errors, service owns transaction use cases, repository owns SQLite/migrations/CAS, storage owns generated paths. Pipeline has no dependency on web/DB/gold. Evaluation reads labels after prediction, never vice versa. Foundation fixture is an explicit mode in same app, not a second deployment.

## 4) Naming and Organization Rules
Python snake_case layer files; frontend PascalCase TSX components under features/documents and app. Public Python imports docintel/document_pipeline; frontend relative imports/generated interfaces, no separate handwritten public schema. No apps/packages move or archive source copies.

## 5) Evidence
backend/src/docintel/api/app.py; services/worker.py; repositories/sqlite.py; frontend/src/main.tsx; frontend/src/features/documents; contracts/README.md; pipeline/pyproject.toml. Other implementations: ../branch-inventory.md at immutable SHAs.
